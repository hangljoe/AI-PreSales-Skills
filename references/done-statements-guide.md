# Done Statements: A Practical Guide

> **Credit.** Study note in our own words. TOC thinking processes originate with Eliyahu M. Goldratt. This tool follows the Black Belt in Thinking programme ([blackbeltinthinking.com](https://blackbeltinthinking.com/)). The method remains the work of its authors.

## What it is

A done statement describes the end state you want, not the work to get there. It is written in the present tense, as if the result already exists, and someone outside the team can confirm it. The difference matters because finishing an output is not the same as creating an outcome. A delivered workshop proves the work happened. It does not prove anything got better.

Three principles, in priority order:
- **Outcome over action** (always). Say what is true when you are done.
- **Clear purpose.** If there is a "why" beyond the action, the statement shows it.
- **Verifiable.** Make it measurable or plainly true/false.

## When to use it in PreSales

- Success criteria for a POC or pilot.
- Intermediate objectives in a PRT, effects in a Transition Tree, and every node in an NCN.
- Mutual action plan milestones, so both sides agree what "complete" means.
- Handover criteria from PreSales to Professional Services.

## Steps

- [ ] Picture the work finished. Ask: "What is different now, and for whom?"
- [ ] Write it in simple present tense. Add a number or a clear true/false test.
- [ ] Leave the method open unless one specific method is genuinely required.
- [ ] If two separate effects are hiding in one statement, split them into a major statement with sub-statements.
- [ ] Check for a baseline. "Cut processing time by half" needs a known starting point.
- [ ] Run the checklist below, then ask a colleague to read it cold.

**Checklist:** Is the outcome obvious from reading it? Is the purpose visible? Can someone else confirm it? Does it allow any tactic? Is it short and plain?

## B2B example

Action: "Run the pilot with the customer's EMEA team."
Done as action: "The EMEA pilot has been completed." (Still just a task.)
Done statement: "The EMEA planners create 95% of weekly replenishment orders in the new system without manual rework."
- Sub-statement: "The planners' supervisor confirms the new process is ready for the other regions."

Watch the wording. "We have fixed the causes of order rework" describes the fixing. "We monitor the causes of rework" describes a mechanism. "95% of orders are correct first time" describes the result. Aim for the last kind.

## Common errors

- **Relabelled outputs.** "Ten training sessions delivered" is still an output, however it is phrased.
- **Vague outcomes.** "Better experience" or "improved efficiency" give no finish line.
- **Done-action disguise.** "We have reviewed the document" is a task in the past tense.
- **Over-prescribing.** Naming the exact method when any method that reaches the result would do.
- **Two goals in one.** Each statement should stand alone.
- **Finished mistaken for improved.** Closing the ticket is not proof of benefit.
