## Phase 6 — Remove Obstacles (Prerequisite Tree — PRT)

**Goal: Identify and sequence what must happen before the injection can be fully applied.**

"What stands in the way becomes the way." Once you name what blocks you, you have also named what you need to do to move past it. The obstacle becomes the path.

*Use horizontal arrows throughout — PRT uses prerequisite logic, not cause-and-effect.*

### PRT rules

**State the goal first** — the future condition that exists when the injection is fully working. Not a task. A condition.

**State obstacles as current conditions**, not missing actions:
- Wrong: "We haven't built the new evaluation process."
- Right: "A standardised evaluation process does not exist."

**State Intermediate Objectives (IOs) as the obstacle being removed:**
"The obstacle no longer exists because [the IO is in place and working]."

**Word every IO as a Done Statement** — present tense, outcome not action, verifiable by someone outside the team.

### Obstacle count: 5–10

- Fewer than 5 usually means the thinking is shallow, or the task is simple enough to skip this tool.
- More than 10 often means several obstacles cluster around one point — break that cluster into its own nested plan.

### Sufficient, not over-sufficient IOs

An IO only needs to be sufficient to clear the obstacle — not the ultimate ideal state.

- Over-sufficient: "We are the best discovery team in the industry." Hard, slow, and not needed.
- Sufficient: "Every discovery call is completed with all 9 FTD fields documented."

If you write an IO and it fails to come true (your first approach doesn't work), you're stuck again — because you wrote an action, not a state. Keep IOs as outcomes, not approaches.

*Keep the obstacle beside each IO. Before pouring effort into a later IO, check the obstacle still exists. Action on earlier IOs often clears later ones — the plan tends to collapse toward the end.*

### PRT structure

| Obstacle (current condition — what exists now that blocks the path) | Intermediate Objective (Done Statement — obstacle removed) | Must precede |
|----------------------------------------------------------------------|----------------------------------------------------------|-------------|
| | | |
| | | Goal state |

**Sequence the IOs** from most foundational to last. Question: "Does this IO need to exist before the next one is achievable?"

### Validation tests for each IO

- **Necessity test:** Does this IO need to exist before the next one can happen? If no, remove the dependency — it is artificially constraining the sequence.
- **Assumption test:** What makes this dependency true? State the assumption. Is it valid?

*Common error: "Too many I-don't-knows." Not knowing is a valid obstacle, but a list full of nothing else means your thinking got too narrow. Ask: "If I knew everything I currently don't, could I reach the goal with no difficulty?" The answer is usually no — dig for the structural obstacles too.*
