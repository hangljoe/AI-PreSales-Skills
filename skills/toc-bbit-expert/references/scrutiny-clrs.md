## Scrutiny — Checking Your Logic (CLRs)

*Use when reviewing any cause-and-effect or prerequisite logic — before acting on analysis, sharing with others, or building the next step on top of it.*

Scrutiny checks logical connections for errors, the same way proofreading checks for grammar. Instead of grammar, you are looking for errors in logic. The basic version (taught here) focuses on clarity. More advanced scrutiny covers accuracy.

Two checks on every logical connection:

### 1. Entity clarity

Is each statement clear on its own?
- Does it make sense as a complete sentence?
- Is it free of ambiguous words, undefined acronyms, or jargon only one person uses?

If not: flag it and rewrite the entity so it accurately reflects what is meant.

### 2. Connection clarity

Does the cause actually lead to the effect as written?
- Even if each statement looks fine individually, can you see the mechanism?
- If it is hard to connect the two boxes, the entities usually have wrong or missing information — the fix is in the entities, not just the arrow.

### How to apply scrutiny

- **Mark issues with a token** rather than stopping to fix immediately. Review the whole connection first, then edit.
- **Be specific.** If one word is the problem, flag that word: "Clarity on 'people'" where it should say "customers."
- **Aim for 3–5 flags per druid side** as a starting point — enough to drive meaningful improvement without overwhelming the author.
- **Work iteratively.** Multiple short rounds produce better results than trying to perfect everything in one go.
- **Match the level to the stakes.** High-cost decisions deserve rigorous scrutiny. Low-stakes analysis can be more relaxed.
