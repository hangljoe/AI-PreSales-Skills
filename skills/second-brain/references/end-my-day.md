# Mode: End My Day

Write today's journal entry in about two minutes of the user's time. Evidence first, then a
three-question interview, then one capped file.

Read `references/conventions.md` first (folder resolution, skeletons, caps, update-safety).

---

## Step 1 — Resolve the brain

Resolve the second-brain root per conventions (memory → env var → ask once).

**First run** (folder or core files missing) — offer the full guided path first: "Want the
guided setup instead (10–15 minutes, one sitting)? It also covers your focus areas, a training
goal, and optional automation — say `/presales:brain:setup`. Or I can do the quick minimal
version right now, in about 8–10 minutes." If the
user wants the quick version (or ignores the offer and just answers), bootstrap interactively here,
creating ONLY what is missing (update-safety rule 1). **Disclose the effort first and offer the
shortcut:** "Quick version: ~8–10 minutes to set up your big rocks and profile properly — or say
'skip' and I'll create minimal stubs now; run `/presales:brain:rocks` when you have time." Then:

1. Create the folder tree (`journal\`, `weekly\`) — Claude Code: PowerShell
   `New-Item -ItemType Directory -Force`; claude.ai: see the Surfaces rule in conventions.
2. `BIG-ROCKS.md` missing → ask 3–4 questions: "What are the 3–5 things this quarter that, if
   they don't happen, the quarter failed? Why does each matter? What does done look like?"
   Draft from the skeleton, show it, adjust, write. (Skipped → stub with `<your rocks here>`.)
3. `PROFILE.md` missing → ask: hot accounts? people whose mail always matters? senders to
   ignore? day boundaries (day start/end time, week-start/week-end day)? Optional: GitHub repos
   / task-tracker sheets or projects (e.g. Smartsheet, Asana, Planner) where tasks are assigned
   to you. Draft, show, write. (Skipped → minimal
   stub.) This quick path does not ask about focus areas, training target, or automation — those
   are Setup mode's job; mention `/presales:brain:setup` can add them anytime.
4. Offer Voice setup as an optional follow-on: "Want me to learn your writing style too?
   (~3 minutes, analyzes your sent mail — run `/presales:brain:voice` anytime)." Don't block on it.
5. Persist the resolved root path in auto-memory, then continue into today's journal below.

## Step 2 — Calendar & mail sweep (if connected)

Any calendar/mail connector works — e.g. Outlook + Teams or Google Calendar + Gmail.

Collect, with caps — this step is silent research, not output:

- Today's **calendar**: which meetings actually happened.
- Mail **sent today** (cap 15, subjects + recipients only) — the best proxy for "what did I work on".
- **The most recent journal** (walk back from today, weekend files included if present — on a
  Monday that's usually Friday's) plus this morning's brief if one was produced: its `Tomorrow`
  intent and open `Carry-overs` are today's checklist to reconcile.

No connection? Skip the calendar/mail evidence — the interview then also asks for Done items
(Step 3).

## Step 3 — The interview (one message, ~2 minutes)

Send ONE message containing the Done draft (from evidence) plus all three questions — never
one question per turn; the user answers once:

1. **Any decisions today I should record — and why?**
2. **Anything blocked or waiting on someone?**
3. **Did a big rock move?** (read the rock names from `BIG-ROCKS.md`)

If no evidence was collected (no calendar/mail connection), open with a fourth item FIRST: **"What did you get done
today? A few bullets is fine."** — otherwise the ✅ Done section would stay empty.

Don't interrogate; accept "nothing" as an answer.

**Unattended run** (invoked by an automation routine, no one present to answer): skip this
interview entirely rather than waiting on a reply that will never come or fabricating one.
Proceed to Step 4 with only what Step 2's evidence sweep supports — leave ⚖️ Decisions and any
new ⏳ Carry-overs empty rather than inventing plausible answers.

## Step 4 — Write the journal

Write `journal/YYYY-MM-DD.md` from the skeleton in conventions, enforcing the skeleton's caps
(defined there — the single source). Mirror the language the user writes in. If today's file
already exists (earlier run), **merge additively per conventions rule 6 — never regenerate**.

- **Carry-overs:** pull every unresolved carry-over from the most recent journal forward,
  preserving each item's original `(since YYYY-MM-DD)` date. Add new blocked items from the
  interview with today's date.
- **Big rocks:** one line per rock — progress or "no movement".
- Links where natural (an email or PR a done-item refers to), per the conventions links rule.
- **If this was an unattended run** (Step 3's interview was skipped): add one line under the
  journal's title, `_(auto-generated by a scheduled run — no interview answered)_`, so a later
  Start My Day/Week run treats this entry as partial evidence, not a confirmed "nothing happened."
- **If this is an unattended scheduled routine specifically** (no filesystem, no human present):
  this step has no way to actually persist the file — per `conventions.md`'s Known limitation
  note, there is usually no working write path on that surface. Don't silently print the
  content as if the write succeeded. Say plainly in the routine's output: "Journal not saved —
  the scheduled routine can't write to your second-brain folder (see conventions.md's Known limitation note)."
  Setup discloses this before anyone schedules this mode; this is the backstop if it runs anyway.

Show the finished file for a ten-second sanity check; apply corrections directly. (Unattended
runs skip this check — there's no one to show it to; the file is simply written.)

## Step 5 — Weekly rollup (last working day)

If today is `PROFILE.md`'s `Day boundaries` week-end day (default: Friday, if that field is
absent) — or the user says it's their last working day this week — also write
`weekly/YYYY-Wnn.md` per the skeleton: distill the week's journals into ✅ Done, ⚖️ Decided,
⏳ Carried into next week, 🪨 Rocks (one status line each). Half a page max. This rollup is how
older weeks stay readable without re-reading dailies — write it tight.

This is the minimal version. For the full weekly review — training-time tally against the
user's target, and a confirm-gated calendar booking if it's short — run
`references/end-my-week.md` (`/presales:brain:end-week`) instead of or in addition to this step;
it reads/enriches the same file rather than rewriting it (conventions rule 6). Mention it once
per user, not every week: check whether any past `weekly/` rollup already has a `🎓 Training`
section (meaning they've used End My Week before) — if none do, say "Want the fuller weekly
review too? `/presales:brain:end-week` — checks your training time and can book a slot if you're
short." Once they've run it at least once, stop mentioning it here.

## Output

The journal file (and the rollup on Fridays), written to the user's second-brain folder, shown
once for confirmation. No other output, no sharing, no publishing.

---

## Quality checklist

- [ ] Existing files untouched except today's journal (+ this week's rollup on Fridays)
- [ ] Caps respected; file ≤ ~60 lines; skeleton headings with icons
- [ ] Carry-overs preserve origin dates; nothing silently dropped from yesterday
- [ ] Every rock from BIG-ROCKS.md has a line (or "no movement")
- [ ] Nothing from the journal quoted anywhere outside the second-brain folder
- [ ] An unattended scheduled run (no filesystem) says plainly it couldn't save, never silently
      prints the content as if it did
