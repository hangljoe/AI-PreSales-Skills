# Mode: Big Rocks

Create or review the user's quarterly priorities in `BIG-ROCKS.md`. Deliberate, human-owned,
slow-changing — this mode is invoked on purpose, roughly quarterly or when priorities shift.

Read `references/conventions.md` first. **Rule: after creation, only this mode (or the human)
edits `BIG-ROCKS.md`. Start My Day reads it, never modifies it; End My Day may CREATE it
during first-run bootstrap (conventions rule 5), never edit it afterwards.**

No second-brain folder at all yet? Create the folder tree per conventions, mention that
`/presales:brain:setup` runs the full guided setup (or `/presales:brain:end` bootstraps the
minimal version), and continue here.

---

## Step 1 — Resolve and read

Resolve the second-brain root per conventions. Read `BIG-ROCKS.md` if it exists; also skim the
last 2–3 weekly rollups if present — they show which rocks actually moved.

## Step 2 — Create (no file yet)

Ask, conversationally:
1. What are the 3–5 things this quarter that, if they don't happen, the quarter failed?
2. For each: why does it matter? What does "done" look like (a checkable success criterion)?

Push back gently on more than 5 ("that's a task list, not big rocks — which two would you
protect if the quarter got cut in half?"). Draft from the conventions skeleton, show, adjust,
write. If the user says "skip" (e.g. mid-`/presales:brain:setup`), don't push back — write a
stub with `<your rocks here>` and move on; they can fill it in later by running this mode again.

## Step 3 — Review (file exists)

Walk the rocks with quarterly-review framing — for each: **keep / done / drop / new**?

- Use rollup evidence: "no movement logged in 4 weeks — still a rock, or admit it's parked?"
- Prompt for status honesty: on track / at risk / **stalled** (stalled is a valid answer, not
  a failure — it just needs to be true).
- Update statuses and `last reviewed:` date. Apply the user's wording — edit surgically, never
  regenerate the file.

## Output

The updated `BIG-ROCKS.md`, shown once for confirmation. Remind the user this now drives the
morning brief's ordering and the no-movement alerts.

- [ ] `last reviewed:` date updated
- [ ] Surgical edits only — user wording preserved
- [ ] No other second-brain file touched
